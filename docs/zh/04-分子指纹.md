# 04 · 分子指纹

指纹是把分子结构压成一个定长向量的办法，也是绝大多数化学机器学习模型的输入。这一章的重点不是「怎么调用」，而是搞清每种指纹到底编码了什么信息——这决定了你选错指纹时会丢掉什么。

## 将化学直觉量化为数值向量

### 04.1 从"看起来像"到"算出来像"

化学家说"这两个分子相似"时，依据的是看见的结构特征——共享的官能团、相似的骨架、相近的分子大小。计算机没有眼睛，它需要一种算法将"结构相似"转化为"数值相似"。

分子指纹正是为此而生。它的核心思想可以用一个比喻理解：

> 指纹不描述分子的"全貌"，而是回答一系列是/否问题："有苯环吗？""有羟基吗？""有碳-氧双键吗？"每个问题的答案（0 或 1）占据向量中的一个位置。这个固定长度的 0/1 向量就是二元指纹。

### 04.2 两类指纹的哲学差异

**结构键（Structural Keys）——"带上清单去验货"**

以 MACCS 指纹为代表。MACCS 包含 166 个预定义的子结构模式（公开的 166 键子集），每个 bit 对应一个专门的化学特征：bit 137 代表"杂环中存在 O"，bit 163 代表"有至少 1 个芳香环"。

```
MACCS 指纹结构：
bit 0: [占位，不使用]
bit 1: 同位素
bit 2: 原子序数 > 103
...
bit 137: 杂环O
...
bit 163: 芳香环计数 > 0
bit 164: 环原子数 > 0
bit 165: 环数 > 1
bit 166: 环数 > 2
```

**优势：** 每个 bit 有明确的化学含义，可以直接解读。"bit 163 = 1"意味着"这个分子有芳香环"，不需要推测。
**劣势：** 如果你的分子含有一个重要的结构特征（比如某种特殊的稠环体系），但清单上没有对应的 key——这个特征就被忽略了，永远不会出现在指纹中。

**哈希指纹（Hashed Fingerprints）——"看到什么记什么"**

以 Morgan/ECFP 指纹为代表。不需要预定义字典，而是从分子自身出发，枚举所有圆形原子环境，通过哈希函数映射到固定长度的向量中。

**哲学差异：** 结构键问"你有这些我事先知道的东西吗？"；哈希指纹说"不管你有什么，都告诉我"。

### 04.3 Morgan 指纹（ECFP）的数学直觉

Morgan 算法最初由 H. L. Morgan 在 1965 年为解决图同构问题提出，后来被 Rogers 和 Hahn（2010）扩展为扩展连接指纹（ECFP）。

**算法核心（迭代实现）：**

1. **初始化：** 每个原子被赋予一个整数 ID，编码其局部属性：
   - 原子序数（6 = 碳，7 = 氮，8 = 氧...）
   - 重原子连接数（degree）
   - 形式电荷
   - 是否为环原子
   - 隐式氢数量

2. **迭代：** 对于 radius = r 的每一轮：
   - 原子 i 收集自身第 r-1 轮的 ID
   - 收集所有邻居 j 的第 r-1 轮 ID
   - 收集连接边 j-i 的键类型
   - 将以上信息合并 → 通过哈希函数 → 产出第 r 轮的新 ID

3. **收集：** 所有原子在所有轮次中产生的所有唯一 ID 构成该分子的特征集合。

4. **折叠（Folding）：** 特征 ID 通过取模运算（ID mod fpSize）映射到固定长度的向量中。

**radius 参数的化学意义：**

```
radius=0: 只编码原子自身（C, N, O...）         → 原子类型
radius=1: 编码原子+直接邻居                    → 官能团级别
radius=2: 编码原子+两层邻居（ECFP4，直径4）      → 官能团+局部环境
radius=3: 编码原子+三层��居（ECFP6，直径6）      → 更大的子结构
```

ECFP4（radius=2）是工业标准的原因：它在"覆盖足够的化学环境"和"保持合理的特异性"之间取得了最佳平衡。radius 太小则两个不同的官能团在指纹中没有区别，radius 太大则指纹变得过于特异化，训练集和测试集之间几乎没有共享的特征。

### 04.4 信息瓶颈：哈希碰撞

哈希指纹有一个固有的取舍：将可能无限的独特子结构映射到有限的 2048 个 bit 中，必然有碰撞。

**碰撞概率（球入箱问题）：** 如果将 n 个特征放入 m 个位置，某个特定特征与其他特征碰撞的概率为：

```
P(碰撞) ≈ 1 - (1 - 1/m)^(n-1)
```

对于典型药物分子（n ≈ 100-500 个唯一子结构）和 fpSize=2048：
- 预期碰撞概率约 5%-22%
- 将 fpSize 加倍到 4096，碰撞概率约减半

**这不是 bug——这是设计取舍。** 更长的指纹减少碰撞但增加存储和计算开销。在 2048 位下，碰撞对大多数 ML 任务的性能影响小于 1%，所以在实践中是合理的妥协。

**计数指纹的缓解作用：** 更精妙的方法是不用 0/1，而是记录每个位置被子结构命中的次数。这样即使碰撞，信息也没有完全丢失——位置值为 3 说明至少有 3 个不同的子结构映射到了这里。计数指纹的信息熵高于同长度的二元指纹，但代价是更复杂的相似性计算。

### 04.5 各指纹类型的互补关系

| 信息类型 | MACCS | Morgan (ECFP4) | Atom Pair | RDKit Topological |
|----------|-------|----------------|-----------|-------------------|
| 原子类型 | ✓ | ✓ | ✓ | ✓ |
| 官能团存在性 | ✓✓（精确匹配166个key） | ✓（通过环境间接捕获） | ✓ | ✓ |
| 局部邻居环境 | ✗ | ✓✓（核心优势） | 部分 | ✓ |
| 原子间拓扑距离 | ✗ | ✗ | ✓✓（核心优势） | ✓（通过路径长度） |
| 线性路径模式 | ✗ | ✗ | ✗ | ✓✓（核心优势） |
| 可解释性 | ✓✓（每个bit有明确含义） | ✗（bit无直接化学含义） | ✓✓（可反推） | 部分 |
| 对分子大小敏感 | 低 | 中 | 高 | 中 |

**实践中的组合策略：** 许多工业级 QSAR 系统同时使用 ECFP4（局部环境）+ MACCS（官能团清单）+ 物理化学描述符（全局性质），将三者拼接为特征向量。这比单一指纹更鲁棒。

## RDKit 中的指纹实现

分子指纹将分子结构编码为固定长度的数值向量——这是将"化学"转化为"数据"的核心桥梁。每种指纹捕获不同类型的结构信息，选择哪种取决于下游任务。

### 04.6 Morgan 指纹（ECFP / Circular Fingerprints）

**核心概念：** 以每个原子为中心，迭代聚合其邻居信息。radius=2 对应 ECFP4（直径 4），是药物化学中最通用的指纹。

**新版 API（推荐）：**

```python
# 创建 Morgan 指纹生成器（ECFP4 = radius 2）
mfpgen = rdFingerprintGenerator.GetMorganGenerator(
    radius=2,        # ECFP4: 直径 4
    fpSize=2048      # 指纹长度（bit 数）
)

# 生成三种形式的指纹
mol = Chem.MolFromSmiles("c1ccccc1O")    # 苯酚

fp_bit = mfpgen.GetFingerprint(mol)           # ExplicitBitVect：0/1 向量
fp_count = mfpgen.GetCountFingerprint(mol)     # 计数向量（精细，但更稀疏）
fp_numpy = mfpgen.GetFingerprintAsNumPy(mol)  # NumPy 数组，直接用于 sklearn

# 获取置位的 bit 列表
on_bits = list(fp_bit.GetOnBits())
print(f"苯酚 ECFP4 置位 bit 数: {len(on_bits)}")

# 查看每个 bit 对应的原子环境（调试/解释用）
bit_info = {}
fp = mfpgen.GetFingerprint(mol, additionalOutput=AllChem.AdditionalOutput())
# bit_info 是 {bit_id: [(atom_idx, radius), ...]}
```

**旧版 API（兼容，但不再推荐用于新项目）：**

```python
# 仍广泛出现在教程和代码中，了解即可
fp_old = AllChem.GetMorganFingerprintAsBitVect(mol, radius=2, nBits=2048)
fp_old_count = AllChem.GetMorganFingerprint(mol, radius=2)    # 计数形式
```

**新旧 API 差异要点：** 默认参数不同，新版默认关闭了 `countSimulation` 和 `includeRedundantEnvironments`，可能导致同分子的指纹 bit 数少于旧版。如需完全对齐旧版行为：

```python
mfpgen = rdFingerprintGenerator.GetMorganGenerator(
    radius=2, fpSize=2048,
    countSimulation=False,              # 精确计数（非泊松近似）
    includeRedundantEnvironments=True    # 保留冗余环境
)
```

### 04.7 MACCS 指纹

166 个预定义的子结构（如"羧基存在"、"芳香环存在"），人为设计，可解释性极强。

```python
from rdkit.Chem import MACCSkeys

mol = Chem.MolFromSmiles("CC(=O)O")    # 乙酸
maccs_fp = MACCSkeys.GenMACCSKeys(mol)

print(f"MACCS 指纹长度: {maccs_fp.GetNumBits()}")    # 167 (第 0 位为占位，有效 166 位)
print(f"置位 bit 数: {maccs_fp.GetNumOnBits()}")

# 查看哪些 bit 被置位
on_bits = list(maccs_fp.GetOnBits())
print(on_bits[:10])    # 前 10 个置位 bit 编号
```

**适用场景：** 分子多样性筛选、快速子结构过滤、可解释的相似性搜索。

### 04.8 RDKit 拓扑指纹（RDKit Fingerprint）

基于分子图中所有指定长度的路径（path）进行哈希。类似 Daylight 指纹。

```python
rdkgen = rdFingerprintGenerator.GetRDKitFPGenerator(
    fpSize=2048,
    minPath=1,
    maxPath=7
)
rdk_fp = rdkgen.GetFingerprint(mol)
```

### 04.9 Atom Pair 指纹

描述分子中每一对原子之间的拓扑距离和原子类型组合。

```python
apgen = rdFingerprintGenerator.GetAtomPairGenerator(fpSize=2048)
ap_fp = apgen.GetFingerprint(mol)

# 查看非零 finger 的含义（解释性）
from rdkit.Chem.AtomPairs import Pairs
# 对于旧版 API 的指纹结果，可以用 ExplainPairScore 解读
# Pairs.ExplainPairScore(bit_id) 返回如: (('C', 1, 0), 3, ('O', 2, 0))
# 含义：有 1 个邻居 0 个 π 电子的 C，通过 3 个键，连到有 2 个邻居 0 个 π 电子的 O
```

### 04.10 Topological Torsion 指纹

描述分子中连续四个原子的序列关系，捕获旋转异构信息。

```python
ttgen = rdFingerprintGenerator.GetTopologicalTorsionGenerator(fpSize=2048)
tt_fp = ttgen.GetFingerprint(mol)
```

### 04.11 指纹选择指南

| 指纹类型 | 长度 | 适用场景 | 特点 |
|----------|------|----------|------|
| Morgan (ECFP4) | 自定义 (1024/2048) | QSAR、虚拟筛选、聚类 | 通用性最强，工业标准 |
| MACCS | 167 | 快速筛选、可解释分析 | 人为设计，含义明确 |
| RDKit Topological | 自定义 | 子结构搜索、多样性分析 | 基于路径，适合子结构互补 |
| Atom Pair | 自定义（稀疏） | 3D 形状相似性补充 | 捕获拓扑距离信息 |
| Topological Torsion | 自定义（稀疏） | 构象相关分析 | 四原子连续序列 |
