# 09 · 化学反应处理

反应是化学区别于其他领域的地方。把「A 加 B 生成 C」写成机器能执行的形式，是虚拟库枚举、逆合成分析、反应条件预测的共同前提。这一章先讲反应如何被形式化，再落到 RDKit 的 `RunReactants` 与产物后处理。

## 从箭头到算法

### 09.1 化学反应的"数据结构"问题

在实验室里，化学反应是用结构式 + 箭头表示的。化学家看一眼就知道"这个羧基和那个胺反应形成酰胺"。但计算机没有化学直觉——它需要在形式化的层面上理解"反应"：

> 反应 = 一组反应物匹配规则 + 原子映射关系 + 产物生成规则

这不是一个抽象问题。逆合成分析和化学反应模板，两者都以反应的形式化表示为前提。

### 09.2 原子映射——反应定义的灵魂

考虑酰胺键形成反应：

```
反应物模板:  [C:1](=[O:2])-[OD1]  .  [N!H0:3]
产物模板:    [C:1](=[O:2])[N:3]
```

`[C:1]` 中的 `:1` 不是注释，它是将反应物中的原子和产物中的原子建立一一对应的机制。这在化学上对应着：**羧基碳（映射 1）在反应前后都是中心碳，它的化学环境变了但身份不变**。

原子映射在计算化学中的等价概念是**反应坐标**（reaction coordinate）——描述原子从反应物状态到产物状态的路径。在 RDKit 的实现中，映射信息在 `RunReactants` 执行后被保存为产物原子的属性（`old_mapno`、`react_idx`、`react_atom_idx`），使得你可以追溯产物中每个原子的来源。

### 09.3 反应模板的两类生成方法

实际工作中会遇到两种反应模板生成方式：

**A. 人工编写（基于化学知识）**

Hartenfeller 等人（2011）收��了 58 个常见有机反应类别的 Reaction SMARTS 模板。这种方法的优势是：
- 每个反应类别有明确的化学含义
- 模板精确，假阳性率低
- 可用于虚拟化合物枚举（"如果给这个骨架加一个酮基会发生什么？"）

劣势是覆盖率有限——如果一个反应不在 58 个模板中，就无法处理。

**B. 数据驱动（从反应数据库中自动提取）**

从 USPTO 或 Reaxys 的反应数据库中，通过分析反应物-产物对，自动提取反应规则。这是逆合成分析软件（如 ASKCOS、AiZynthFinder）的核心技术之一。

**反应中心的识别是关键步骤**——确定哪些原子和键在反应前后发生了变化（形成/断裂）。

### 09.4 RunReactants 的组合爆炸问题

当反应物有多个匹配位置时，`RunReactants` 会枚举所有可能的组合。这在一个羧基上运行酯化反应时不严重（通常只有 1-3 个匹配），但在多官能团分子上运行通用反应模板时可能导致组合爆炸。

这就是为什么逆合成分析需要搜索策略（如 Monte Carlo Tree Search）而不是简单地枚举所有可能性——搜索空间随着反应步数呈指数增长。

## RDKit 中的反应操作

化学反应处理是逆合成分析和虚拟化合物枚举的基础。RDKit 使用 Reaction SMARTS（SMARTS 的超集）来定义反应模板。

### 09.5 Reaction SMARTS 语法

Reaction SMARTS 的结构：

```
反应物 >> 试剂（可选）>> 产物
```

原子映射是核心机制——用 `:数字` 标记，指明反应物中的哪个原子变成了产物中的哪个原子。

```python
from rdkit import Chem
from rdkit.Chem import AllChem, Draw, rdChemReactions

# 酰胺键形成：羧酸 + 胺 → 酰胺 + 水
# [C:1] 表示羧基碳被映射为编号 1，在产物中保持该映射
amide_formation = AllChem.ReactionFromSmarts(
    '[C:1](=[O:2])-[OD1].[N!H0:3]>>[C:1](=[O:2])[N:3]'
)

# 可视化反应
img = Draw.ReactionToImage(amide_formation)
img.show()
```

关键 SMARTS 原子表达式速查：

| 表达式 | 含义 |
|--------|------|
| `[OD1]` | 连接度为 1 的氧（羟基 O） |
| `[N!H0]` | 至少连一个 H 的氮（伯/仲胺） |
| `[CD3]` | 连接三个重原子的碳 |
| `[c:1]` | 芳香碳，映射编号 1 |
| `[$(C-c1ccccc1)]` | 递归 SMARTS：连在苯环上的碳 |

### 09.6 运行反应

```python
# 准备反应物
acid = Chem.MolFromSmiles('CC(=O)O')        # 乙酸
amine = Chem.MolFromSmiles('NC')            # 甲胺
reactants = (acid, amine)

# 运行反应
products = rxn.RunReactants(reactants)

# products 是 list[tuple] 结构
# 外层 list：每个元素对应一个匹配组合
# 内层 tuple：该匹配产生的各产物分子
print(f"匹配组合数: {len(products)}")
print(f"第一个产物: {Chem.MolToSmiles(products[0][0])}")  # CNC(C)=O
```

### 09.7 多匹配场景

当一个反应物有多个可匹配位置时，`RunReactants` 会枚举所有可能性。

```python
# 含两个羧基的分子
diacid = Chem.MolFromSmiles('C(COC(=O)O)C(=O)O')
ps = amide_formation.RunReactants((diacid, amine))

print(f"产物数: {len(ps)}")  # 2（每个羧基位置一个）
for i, p in enumerate(ps):
    print(f"  产物 {i+1}: {Chem.MolToSmiles(p[0])}")
```

### 09.8 产物后处理

```python
def run_and_clean_reaction(rxn, reactants):
    """运行反应并返回去重、标准化后的产物列表"""
    products = rxn.RunReactants(reactants)
    results = set()
    for product_set in products:
        for mol in product_set:
            try:
                Chem.SanitizeMol(mol)
                results.add(Chem.MolToSmiles(mol))
            except Exception:
                pass
    return sorted(results)

unique_products = run_and_clean_reaction(amide_formation, (diacid, amine))
print(unique_products)
```

### 09.9 产物原子溯源

RDKit 2024.09+ 版本在产物原子上自动附加了溯源信息：

```python
prod = products[0][0]
for atom in prod.GetAtoms():
    props = atom.GetPropsAsDict(includePrivate=False)
    if 'react_idx' in props:
        print(f"产物原子 {atom.GetIdx()}: 来自反应物 {props['react_idx']}, "
              f"原反应物中的原子索引 {props['react_atom_idx']}")
        if 'old_mapno' in props:
            print(f"  模板映射编号: {props['old_mapno']}")
```
